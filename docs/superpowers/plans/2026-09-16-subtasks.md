# Implementation Plan: Subtasks

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a task be broken down into subtasks that are full, independent `Task` records — placeable on any board in the same project, linked to their parent via a one-level-deep `parent_task_id`, surfaced through a "Subtasks" tab, progress badge, and parent-link badge.

**Architecture:** Backend extends the existing `internal/handlers` kanban module (no new handler file, no new layer): `task_handler.go` gains subtask-aware `CreateTask` validation and a `GetSubtasks` handler, `kanban_dto_builder.go` gains batched subtask-progress/parent-ref resolution, `kanban_handler.go`'s `UpdateColumn` gains single-done-column enforcement. Frontend follows the existing per-concern service/hook pattern (mirroring `activity-log.service.ts`/`use-activity-log.ts`), adds a `SubtasksTab` alongside the existing Description/Attachments/Comments/History tabs, and fixes a cross-board task-open gap discovered during research.

**Tech Stack:** Go 1.x / Fiber v2 / GORM / PostgreSQL (backend, container `devbridge_backend`), Next.js / React / TypeScript / Zustand (frontend, container `devbridge_frontend`), both live via `docker compose` (`devbridge_backend`, `devbridge_frontend`, `devbridge_postgres`).

**Spec:** `docs/superpowers/specs/2026-09-16-subtasks-design.md`

## Corrections to the spec (discovered during file-boundary research, applied below)

1. **Cross-board task-open is not actually wired on the frontend.** The spec's Frontend
   section claims opening a parent/subtask badge "works across boards without navigation,
   because task fetching (`GET /projects/:id/tasks/:taskId`) is already board-independent."
   The backend endpoint genuinely is board-independent (`task_handler.go`'s `GetTask` does a
   plain `database.GetDB().First(&task, taskID)`, no board/project filter) — but the frontend
   never calls it. `TaskDetailModal.tsx` and every tab under it read the task only via
   `useTasks(projectId).getTask(taskId)` (`use-tasks.ts:127-129`), a pure synchronous
   `tasks.find(...)` lookup against the Zustand store with no API fallback. Opening a
   parent/subtask that lives on a board never loaded into the store renders with
   `task === undefined` (blank modal). Task 11 below fixes this with a store-miss fallback
   fetch in `TaskDetailModal.tsx`, pushed into the store via the store's existing `addTask`
   action (which already safely no-ops the per-column push when the task's `columnId` isn't
   in any loaded column — confirmed in `kanban.store.ts:198-206`).
2. **No Go test suite exists in this repo** (`find ... -name "*_test.go"` returns zero
   results; `go.mod` has no test-framework dependency), and the frontend has no test runner
   configured either (no `test` script in `package.json`, no `*.test.*`/`*.spec.*` files).
   The spec's Testing section calls for `go test ./...` and new handler tests, but there is no
   existing test infrastructure to extend. Per this repo's own prior shipped plan
   (`docs/superpowers/plans/2026-09-04-task-detail-history.md`), the actual established
   verification convention is `docker exec devbridge_backend go build ./... && go vet ./...`
   plus live curl checks, and `docker exec devbridge_frontend npx tsc --noEmit` plus manual
   walkthrough on the frontend. Every task's Verification section below uses this convention.
3. **`CreateTaskRequest.ParentTaskID` is `string`, not `*uint`.** The spec says `*uint`, but
   every other foreign-key-like field on that same request struct (`BoardID`, `ColumnID`,
   `AssigneeID`) is `string`, converted server-side via `models.StrToID`. Task 2/4 below follow
   that existing convention instead.

## Global Constraints (binding for every task below)

- Run all Go/Node tooling only via `docker exec devbridge_backend ...` / `docker exec devbridge_frontend ...` — never on host.
- No new dependency, package, or infra component — everything below reuses `gofiber`, `gorm`, existing React/TS patterns already in the repo.
- No commits/pushes at any point unless explicitly requested — leave changes in the working tree.
- Live verification (curl / manual browser check) only against the local compose stack; no production/shared data.
- Any QA project/board/task/column created for verification must be deleted afterward.
- Subtask nesting is strictly one level deep, enforced both server-side (`CreateTask` rejects a `parentTaskId` that already has its own `parentTaskId`) and client-side (Subtasks tab hidden on a task that has a `parentTask`). No code path may re-parent an existing task after creation.

```go
// subtaskProgressByParent batch-computes {total, done} subtask counts for every
// id in parentIDs that has at least one subtask, in a single grouped query.
// "done" counts subtasks whose current board placement sits in an is_done column;
// a subtask with no placement, or placed only in non-done columns, counts toward
// total but not done.
func subtaskProgressByParent(parentIDs []uint) map[uint]models.SubtaskProgressDTO {
	result := make(map[uint]models.SubtaskProgressDTO)
	if len(parentIDs) == 0 {
		return result
	}

	type row struct {
		ParentTaskID uint
		Total        int
		Done         int
	}
	var rows []row
	database.GetDB().Raw(`
		SELECT t.parent_task_id AS parent_task_id,
		       COUNT(DISTINCT t.id) AS total,
		       COUNT(DISTINCT t.id) FILTER (
		           WHERE EXISTS (
		               SELECT 1 FROM task_placements tp
		               JOIN kanban_columns kc ON kc.id = tp.column_id
		               WHERE tp.task_id = t.id AND kc.is_done = true
		           )
		       ) AS done
		FROM tasks t
		WHERE t.parent_task_id IN ? AND t.is_archived = false
		GROUP BY t.parent_task_id
	`, parentIDs).Scan(&rows)

	for _, r := range rows {
		result[r.ParentTaskID] = models.SubtaskProgressDTO{Total: r.Total, Done: r.Done}
	}
	return result
}

// parentTaskRefsByID batch-loads {id, title} for a set of task ids, used to
// resolve the parentTask reference on a subtask's own DTO.
func parentTaskRefsByID(ids []uint) map[uint]models.TaskParentRefDTO {
	result := make(map[uint]models.TaskParentRefDTO)
	if len(ids) == 0 {
		return result
	}
	var rows []models.Task
	database.GetDB().Select("id, title").Where("id IN ?", ids).Find(&rows)
	for _, t := range rows {
		result[t.ID] = models.TaskParentRefDTO{ID: models.IDToStr(t.ID), Title: t.Title}
	}
	return result
}
```

- [ ] **Step 6: Add `loadSubtaskDTOs`**, at the end of the file, mirroring `loadTaskDTOs`'s batching pattern but filtered by `parent_task_id` instead of `project_id` (avoids N+1 queries when `GetSubtasks`, added in Task 5, serves a parent with many subtasks):

```go
// loadSubtaskDTOs loads all (non-archived) subtasks of a given parent task, each
// resolved with its earliest known board placement (a subtask is usually placed on
// exactly one board — if placed on more than one, this only affects the informational
// columnId shown on the subtask row, not the parent's own subtaskProgress count computed
// by subtaskProgressByParent above). Subtasks are one level deep only, so every returned
// DTO's own subtaskProgress is nil.
func loadSubtaskDTOs(parentTaskID uint) ([]models.TaskDTO, error) {
	var tasks []models.Task
	if err := database.GetDB().Where("parent_task_id = ? AND is_archived = false", parentTaskID).
		Order("id ASC").Find(&tasks).Error; err != nil {
		return nil, err
	}
	if len(tasks) == 0 {
		return []models.TaskDTO{}, nil
	}

	taskIDs := make([]uint, len(tasks))
	userIDs := make([]uint, 0, len(tasks)*2)
	for i, t := range tasks {
		taskIDs[i] = t.ID
		userIDs = append(userIDs, t.CreatedBy, t.UpdatedBy)
		if t.AssigneeID != nil {
			userIDs = append(userIDs, *t.AssigneeID)
		}
	}

	var placements []models.TaskPlacement
	database.GetDB().Where("task_id IN ?", taskIDs).Order("id ASC").Find(&placements)
	placementByTask := make(map[uint]models.TaskPlacement, len(placements))
	for _, p := range placements {
		if _, exists := placementByTask[p.TaskID]; !exists {
			placementByTask[p.TaskID] = p
		}
	}

	var comments []models.TaskComment
	database.GetDB().Where("task_id IN ?", taskIDs).Order("created_at ASC").Find(&comments)

	var entries []models.TaskTimeEntry
	database.GetDB().Where("task_id IN ?", taskIDs).Order("date DESC").Find(&entries)

	var attachments []models.Attachment
	database.GetDB().Where("task_id IN ?", taskIDs).Order("created_at ASC").Find(&attachments)

	for _, c := range comments {
		userIDs = append(userIDs, c.UserID)
	}
	for _, e := range entries {
		userIDs = append(userIDs, e.UserID)
	}
	for _, a := range attachments {
		userIDs = append(userIDs, a.UploadedBy)

	users := loadUsersByIDs(userIDs)
```

```ts
'use client';

import { useState, useCallback } from 'react';
import { subtaskService } from '@/services/kanban';
import type { Task, CreateTaskData } from '@/types/kanban';

interface UseSubtasksReturn {
    subtasks: Task[];
    isLoading: boolean;
    error: string | null;
    loadSubtasks: () => Promise<Task[]>;
    addSubtask: (data: CreateTaskData) => Promise<Task>;
}

export const useSubtasks = (projectId: string, parentTaskId: string): UseSubtasksReturn => {
    const [subtasks, setSubtasks] = useState<Task[]>([]);
    const [isLoading, setIsLoading] = useState(false);
    const [error, setError] = useState<string | null>(null);

    const loadSubtasks = useCallback(async () => {
        setIsLoading(true);
        setError(null);
        try {
            const data = await subtaskService.getSubtasks(projectId, parentTaskId);
            setSubtasks(data);
            return data;
        } catch (err) {
            setError(err instanceof Error ? err.message : 'Failed to load subtasks');
            throw err;
        } finally {
            setIsLoading(false);
        }
    }, [projectId, parentTaskId]);

    const addSubtask = useCallback(async (data: CreateTaskData): Promise<Task> => {
        const subtask = await subtaskService.createSubtask(projectId, parentTaskId, data);
        setSubtasks((prev) => [...prev, subtask]);
        return subtask;
    }, [projectId, parentTaskId]);

    return { subtasks, isLoading, error, loadSubtasks, addSubtask };
};
```
